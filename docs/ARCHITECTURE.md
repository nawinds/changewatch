# Архитектура

ChangeWatch — модульный монолит: один Spring Boot сервер и PostgreSQL.

| Модуль | Ответственность |
| --- | --- |
| core | Модели таблицы и монитора, выбор строки, правила сравнения, порты хранения и SheetFetcher |
| identity | Создание аккаунта и проверка Bearer-токена по SHA-256 хешу |
| monitoring | Источники Google Таблиц, личные мониторы, проверки и история |
| storage | JDBC-репозитории, транзакции и миграции Flyway |
| server | Сборка приложения, REST API, Google Sheets CSV export и планировщик |

`identity`, `monitoring` и `storage` зависят только от `core`. `server` связывает модули.
Единственный адаптер внешних данных — `GoogleSheetsFetcher`. Он получает CSV по идентификаторам
таблицы и листа. URL формируется приложением; переходы разрешены только на Google HTTPS-хосты.
Загрузка ограничена таймаутом, числом переходов и размером ответа. Commons CSV разбирает ячейки
с кавычками и переносами строк; заголовки и размеры таблицы проверяются до сравнения.

## Данные и проверка

- `accounts`: имя и хеш токена.
- `sources`: уникальная пара spreadsheet_id/sheet_id, интервал, сроки и ошибка загрузки.
- `monitors`: владелец, строка, столбцы, правило, состояние и последняя база.
- `changes`: столбец, старое и новое значения, тип, результат правила и время.

Проверка блокирует источник через `FOR UPDATE NOWAIT`, проверяет срок, загружает таблицу,
выбирает строки активных мониторов и сохраняет изменения. История, базы и следующий срок
сохраняются одной транзакцией. Первая проверка монитора создаёт базу без событий.
Ошибка выбора строки сохраняется у монитора, не меняя его базу. Ошибка загрузки сохраняется
у источника и переносит следующую попытку; успешные данные остаются прежними.

Ручная проверка и планировщик вызывают один `CheckService`. Конкурентная проверка получает 409.
Создание, пауза и удаление монитора берут ту же блокировку источника. Для простоты транзакция
остаётся открытой во время загрузки. Планировщик последовательно обрабатывает до 20 источников
за проход; источники без активных мониторов не выбираются.

Доступ к монитору и истории проверяется по owner_id. Удаление монитора удаляет его историю через
`ON DELETE CASCADE`. Общие источники содержат только публичные таблицы и доступны авторизованным аккаунтам.
