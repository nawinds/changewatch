# ChangeWatch

Сервер на Kotlin и Spring Boot для мониторинга публичных Google Таблиц.
Пользователь выбирает строку по значению ключевого столбца и столбцы для наблюдения.
Сервер периодически загружает CSV из Google Sheets, сравнивает значения и сохраняет историю в PostgreSQL.

## Возможности

- Аккаунт с персональным Bearer-токеном, доступ только к своим мониторам и истории.
- Одна загрузка на все подписки на одинаковые `spreadsheetId` и `sheetId`.
- Выбор строки по точному значению, например `Студент = Аксенов Никита`. Порядок строк и столбцов может меняться.
- Создание, просмотр, пауза, возобновление и удаление мониторов.
- Проверки по расписанию или вручную с интервалом 30–86400 секунд.
- Правила `ANY_CHANGE`, `VALUE_APPEARED`, `INCREASED`, `DECREASED`.
- История со старыми и новыми значениями, временем и результатом правила.

Первое успешное чтение устанавливает базу без событий. Пустая ячейка, `—` и `-` означают отсутствие значения.
Числовые правила сравнивают десятичные числа с точкой. История сохраняет все изменения; `matchedOnly=true` оставляет сработавшие по правилу.
Если строка отсутствует, неоднозначна или пропал столбец, монитор получает ошибку и сохраняет прежнюю базу.
Ошибка загрузки также не меняет последнюю успешную базу. После паузы сравнение продолжается с сохранённых значений.

## Запуск

Нужен Docker с Compose:

```bash
cp .env.example .env
# Задайте POSTGRES_PASSWORD в .env
docker compose up --build -d
curl http://localhost:8080/actuator/health
```

API: `http://localhost:8080/api/v1`. Порты доступны только на localhost; их можно поменять через `APP_PORT` и `DB_PORT` в `.env`.
`docker compose down` останавливает приложение и сохраняет данные. Параметр `-v` удаляет данные.

## Подключение таблицы

1. В первой строке таблицы задайте уникальные заголовки, например `Студент`, `Lab 1`, `Lab 2`.
2. Добавьте строку `Аксенов Никита`, `—`, `—` и включите доступ «Все, у кого есть ссылка — Читатель».
3. Из адреса `https://docs.google.com/spreadsheets/d/SPREADSHEET_ID/edit#gid=0` возьмите `SPREADSHEET_ID` и числовой `sheetId` из `gid`.
4. Выполните запросы из [docs/api.http](docs/api.http): создайте аккаунт, источник и монитор. Подставляйте идентификаторы и токен из ответов.
5. Дождитесь `initialized=true` у монитора, измените балл и после следующей проверки получите историю.

Google может обновлять CSV с задержкой. Поддерживаются публичные таблицы до 200 столбцов, 10000 строк и 2 MB.
Имена заголовков после удаления крайних пробелов должны быть непустыми и уникальными.
Токен выдаётся один раз; восстановления доступа и Google OAuth нет. Подключайте только таблицы, данные которых можно публиковать.

## API

Префикс всех путей — `/api/v1`. Кроме создания аккаунта, нужен `Authorization: Bearer <token>`.

| Метод и путь | Назначение |
| --- | --- |
| POST /accounts | `{name}`, создать аккаунт и получить токен |
| GET /me | Текущий аккаунт |
| POST /sources | `{spreadsheetId, sheetId=0, intervalSeconds=60}`, создать или найти источник |
| GET /sources/{id} | Состояние таблицы и ошибка загрузки |
| POST /monitors | `{sourceId, name, rowKey, rowValue, columns, rule=ANY_CHANGE}` |
| GET /monitors | Свои мониторы |
| GET /monitors/{id} | Значения и состояние монитора |
| PATCH /monitors/{id} | `{active:false}` — пауза; `{active:true}` — возобновление |
| DELETE /monitors/{id} | Удалить монитор и историю |
| POST /monitors/{id}/check | Проверить таблицу и все её активные мониторы |
| GET /monitors/{id}/changes | История от новых изменений к старым |

Списки принимают `limit` (1–100, по умолчанию 50) и `offset` (0–1000000, по умолчанию 0).
История также принимает `matchedOnly` (по умолчанию false).
Интервал общего источника задаёт первый создавший его пользователь. Ручная проверка соблюдает тот же интервал.
Источник без активных мониторов не опрашивается.

Ошибки возвращаются как `application/problem+json`: 400 — неверные данные, 401 — неверный токен,
404 — ресурс отсутствует или чужой, 409 — источник занят или срок проверки ещё не наступил,
502 — ошибка Google Sheets, 500 — внутренняя ошибка.

## Устройство и разработка

Один JVM-процесс и одна PostgreSQL. Модули `identity`, `monitoring` и `storage` зависят от `core`;
`server` собирает приложение. Подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Границы продукта — в [docs/VISION.md](docs/VISION.md).

Для локальной сборки нужны JDK 25 и Docker для интеграционных тестов:

```bash
./gradlew test
./gradlew :server:installDist
```

Тесты проверяют CSV, выбор строки, правила, HTTP API, доступ, историю, блокировки и откат транзакций.
Интеграционные тесты запускают PostgreSQL через Testcontainers; Google заменён тестовым адаптером.

Для запуска из IDE поднимите БД командой `docker compose up -d postgres`, задайте `DATABASE_URL`,
`DATABASE_USER`, `DATABASE_PASSWORD` и выполните `./gradlew :server:run`.
По умолчанию URL БД — `jdbc:postgresql://localhost:5432/changewatch`, пользователь — `changewatch`.
Конфигурация также принимает `PORT` (8080), `SCHEDULER_ENABLED` (true), `SCHEDULER_DELAY_MS` (5000), `LOG_LEVEL` (INFO).
Для ручного режима установите `SCHEDULER_ENABLED=false`.
